### What does this PR do?

**[1/2]** of a two-PR series on V1 in-flight liveness; **[2/2]** (dead agent-loop worker detection and relaunch) stacks on this one.

Opt-in recovery for a V1 TransferQueue training step whose prompt lost its writer. Only the `AgentLoopWorkerTQ` that runs a prompt group writes its terminal status; if its generation silently never returns (an engine RPC that hangs, a tool that never answers; #6583 is this class) the group stays `running` forever and sync `ReplayBuffer.sample` / async `wait_for_sampleable` poll forever (`_reissue_inflight_prompts` only runs at `fit()` start). Reproduced on CPU with the real classes before writing this (`research/vet/E4/repro_replay_wait_hang.py`).

Three sampler keys, inert unless `inflight_ttl_s` is set; behaviour is otherwise unchanged:

- `trainer.v1.sampler.inflight_ttl_s` (default `null`): prompts carry a `dispatched_at` tag; a `pending`/`running` training prompt older than the TTL is re-issued mid-run under a fresh uid (`attempt + 1`; old rows discarded, late writes of the retired attempt swept) and sampling keeps polling. The TTL is dispatch-to-terminal **including engine queueing**: set it above the largest `timing_s/gen` of a healthy run.
- `trainer.v1.sampler.max_inflight_reissues` (default 3): after that many re-issues a prompt becomes a `failure` group under a fresh uid and the existing failure paths (padding, `sync_refill_failed_groups`, async failure refill) finish the step; a capped prompt is not trained in this epoch.
- `trainer.v1.sampler.max_inflight_reissues_per_step` (default `null` = `(max_inflight_reissues + 1)` x `data.train_batch_size`): the per-prompt cap alone does not bound a step, because the refill that replaces an exhausted prompt starts at attempt 1. Every TTL-induced discard is charged against the budget, a re-issue or the failure that ends an exhausted prompt (which makes the refill path start another generation), counted per training step across the sampling calls that share a `global_steps` (`parameter_sync_step` mini-batches, the `separate_async` switch wait). Once spent, the TTL retires nothing more in that step and the sampler waits for the in-flight generations exactly as without a TTL (one warning per step, `training/inflight_ttl_suspended=1` in the sampling call that held one back), so pending healthy work completes and the step returns; the sync DAPO drain's discard of surplus in-flight groups is not charged. Without `sync_refill_failed_groups` (sync mode's default) a failed group is padded, never replaced, so the sampler never lets the TTL fail its last finishable groups: when an exhaustion failure would leave no finished group and nothing else in flight, the groups are held back for that poll (flag, one warning per step) and their generations are waited for; the check is repeated every poll and charges nothing, so once another group is finished or in flight the exhausted prompt is failed under the normal budget (a dead writer beside a healthy slow group is padded as soon as the healthy group finishes). `max_inflight_reissues=0` never re-issues: an expired prompt is failed on its first expiry, under the same budget. The key must be a positive integer or `null`.

What is proven (CPU: the real sampling loops with an in-memory TransferQueue and a virtual clock, and the real buffer) and what is not: TTL-induced discards per step are bounded by the budget; a step never loses its last finishable group to the TTL; after that the sampler waits for the in-flight generations, so a TTL below the honest generation time costs at most that many regenerations and then degrades to `main`'s behaviour. A generation that truly never returns still blocks the step once the budget is spent, as on `main`; an explicit wait-vs-abort policy at that point is a follow-up, not implemented here. A re-issue dispatched to a dead worker still raises `RayActorError` as on `main` (loud, not a hang); detection and relaunch are [2/2]. Validation prompts are never regenerated (the TTL does not apply to `val`); with this PR alone a worker that dies during validation still blocks `_validate`, as on `main`, until [2/2].

Also: `AgentLoopManagerTQ.generate_sequences` starts each batch at a rotating worker index, so a re-issue or refill batch smaller than the worker count is not pinned to worker 0. This changes the default chunk-to-worker mapping (chunk `i` goes to worker `(start + i) % num_workers` instead of worker `i`; same chunking, same prompts per worker, same placement; nothing observes which worker ran a prompt). The restart-time re-issue drops restored rows no prompt refers to any more; the new counters are summed across `parameter_sync_step` iterations in `MetricsAggregator`.

Boundary: rollout replica health, `update_weights` fencing and load-balancer membership are #8168 and RFC #8380 and are not touched. #7910 is V0-only standby trainer workers. #6641 makes the legacy `main_ppo_sync` replay buffer fail closed on partial rollout groups (it raises; this PR recovers, in the V1 buffer of `trainer_base`); no shared code. #8203 (streaming dataloader actor, BREAKING) moves the host module; every hunk here is additive and maps onto `StreamingDataloader` (see Design); happy to rebase onto it if it lands first.

New metrics: `training/inflight_reissued`, `training/inflight_reissue_exhausted`, `training/inflight_discarded_while_draining` (totals per step), `training/inflight_ttl_suspended` (a per-step 0/1 flag, reduced as a max) and `training/inflight_expired_age_max` (a max). ### Design & Code Changes

- `trainer_base.py`: `_submit_batch_to_rollout` stamps `dispatched_at` and `attempt` in the prompt tag and persists the prompt rows in sync mode when the TTL is set (async already did). `_reissue_inflight_prompts(partition_id, uids=None)`: `uids=None` is the restart-time path (now also drops restored rows without a prompt group); with `uids`, only those still in flight are restarted under a FRESH uid with `attempt + 1`, old trajectories cleared, the retired uids returned. The buffer is wired with the three keys and `reissue_fn`.
- `replay_buffer.py`: `_expired_inflight_keys`, `_sweep_retired_attempts`, `_fail_exhausted`, `_reissue_budget`, `_begin_ttl_budget`, `_within_reissue_budget`, `_recover_stuck_inflight(..., reissue_budget)` called on every poll of sync `sample` (with the DAPO `draining` flag) and async `wait_for_sampleable`; it re-checks TransferQueue right before acting and retires only what the trainer actually replaced, so a group that turned terminal in the window is never lost. The counter lives on the buffer keyed by the `global_steps` of the sampling calls (shared by a step's calls, reset by the next step) and charges every TTL-induced discard, a re-issue or an exhaustion failure (the drain's discard is exempt); expired prompts are retired oldest-first up to the remaining allowance. The padding-mode sampler passes `keep_last_finishable`, so `_hold_back_last_groups` holds the step's last finishable groups back for the poll (charging nothing) instead of failing them; the direct recovery call keeps the raw semantics. The trainer wires `train_batch_size` in every mode for the default.
- `agent_loop_tq.py`: rotating dispatch start index. `utils.py`: the counters in the `sum` list. Config: three keys + regenerated `_generated_*.yaml`. Docs: `docs/advance/v1_async_trainer.md` "Self-healing".
- On #8203: the buffer hunks move to `StreamingDataloader._advance_request` / `poll_once` (after `_sync_metadata_from_transfer_queue`), the per-step counter onto the actor keyed by the request's `global_steps`, the stamp into `tq_schema.prompt_tag`, the re-issue into the actor's `_reissue_inflight_prompts`; the callable kwarg disappears (plan in the package).
- Known limit: a retired attempt is not aborted; its engine requests run to completion and their rows are swept. A worker-side cancel of retired uids is a follow-up.
