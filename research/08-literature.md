### Appendix A. vLLM suffix-decoding internals (relevant to rank 2's zero-code baseline)

From `vllm/v1/spec_decode/suffix_decoding.py` (read via GitHub API 2026-10-28) and `docs/features/speculative_decoding/suffix.md`:
- `SuffixDecodingProposer` wraps Arctic Inference's `SuffixDecodingCache(max_tree_depth, max_cached_requests)`; the docstring says the object "will take care of caching request outputs, evicting old requests, and manages the per-prompt suffix trees".
- Per request: `start_request(req_id, prompt_token_ids)` builds a suffix tree over the prompt; every step `add_active_response(req_id, sampled_ids)` appends the new tokens; `speculate(req_id, pattern=last max_tree_depth tokens, max_spec_tokens, max_spec_factor, min_token_prob)` returns a variable-length draft; when a request leaves the batch `stop_request(req_id)` moves its response into the global cache (bounded by `max_cached_requests`, LRU eviction).
- Consequence for verl: the global cache lives in the EngineCore process and persists across generate calls, i.e. across verl steps and weight syncs (verification is exact, so stale drafts cost only acceptance rate). In a GRPO step it therefore already contains (a) the request's own prompt, (b) siblings of the same prompt that finished earlier (Seer's "group context"), and (c) the previous steps' responses of other prompts; what it lacks versus HistoSpec/SPEC-RL is per-prompt keying of the previous epoch's response for the same prompt (the ~93%-token-acceptance source in RhymeRL). Docs name "RL rollouts" as a target workload; `pip install arctic-inference` is the only dependency; `num_speculative_tokens` is a maximum (docs example 32). vLLM's docs dir also lists `dynamic_speculative_decoding.md` and `acceptance_metrics.md` (batch-size-aware adaptation and metrics), i.e. the "batch-size gating" RhymeRL/Seer implement by hand.
- Open check before building anything: verl's rollout needs per-token log-probs (`calculate_log_probs`) with speculative decoding active — the MTP path already does this, so it is expected to work, but confirm `rollout/spec_accept_*` metrics and `rollout_log_probs` under `method: suffix`.
